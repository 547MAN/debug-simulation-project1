# AI Code Debugging Simulation — Project 1

## Overview

This repository is a hands-on experiment in understanding, debugging, and improving **AI-generated code**.

I plan to use AI to generate a software project containing bugs, questionable design choices, or other imperfections. My challenge is to **find and fix those problems myself**: read the code, reproduce and investigate issues, research possible solutions, and implement and test my own changes instead of simply asking AI for the answers.

The purpose is not just to make the project work. It is to become more proficient at working with code I did not write—particularly code produced by AI.

## Why I'm Doing This

As AI-assisted programming becomes more common, developers increasingly need to evaluate and maintain code they did not author. AI output can look convincing while still containing logical errors, unnecessary complexity, fragile assumptions, or poorly structured implementations.

I want to learn how to recognize that kind of **"AI slop,"** understand why it fails, and determine what can be salvaged, rewritten, or improved. The aim is to turn imperfect generated code into something more reliable, readable, and maintainable through my own reasoning and research.

## Learning Goals

- **Read unfamiliar AI-written code:** Trace its structure, logic, dependencies, and intended behavior.
- **Detect and diagnose bugs:** Reproduce issues and investigate their root causes rather than guessing at fixes.
- **Research independently:** Consult documentation, technical references, and other learning resources to develop possible solutions.
- **Implement and validate fixes:** Make changes myself, test them, and check for unintended side effects.
- **Improve code quality:** Refactor confusing, inefficient, or unnecessarily complex implementations when appropriate.
- **Document the process:** Record findings, decisions, mistakes, fixes, and lessons learned.

## Planned Workflow

1. **Generate:** Use AI to produce the initial project, including imperfect or buggy code.
2. **Explore:** Read through the codebase to understand what the program is meant to do and how it works.
3. **Investigate:** Run the project, identify problematic behavior, reproduce errors, and isolate likely causes.
4. **Research:** Study relevant concepts and documentation, then evaluate potential fixes.
5. **Implement:** Write and apply my own solutions, including refactoring where it makes sense.
6. **Verify and reflect:** Test the results and document what changed, why it worked, and what I learned.
